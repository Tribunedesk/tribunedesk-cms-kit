# tdkit 1.1 — poziom 4 — plan wykonania

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `tdkit check --levels 4` sprawdza integrację biblioteki mediów według przewodnika 4, atrapa obsługuje wszystkie trasy poziomu 4 i trzy odroczone punkty E9 D6, a skill prowadzi integratora przez poziom 4.

**Architecture:** Stan poziomu 4 w osobnym module atrapy (`mock/media.py`, czyste funkcje na dataclassach, bez HTTP), trasy w `mock/media_routes.py` podpięte do istniejącego `MockServer`. `check` dostaje komendy poziomu 4 w `CheckOptions`/`Context`, scenariusze w `check/scenarios_media.py`. Dowodem jest integracja wzorcowa `tests/reference_media.py` z flagami łamiącymi po jednej regule.

**Tech Stack:** Python 3.12, biblioteka standardowa + `jsonschema==4.23.0` (bez nowych zależności), pytest, ruff, pyright.

**Spec:** `docs/specs/2026-11-13-tdkit-1-1-poziom-4-design.md` (zatwierdzony 13.11). Kontrakt: tag `v3.4.2-draft` repo `Tribunedesk/tribunedesk-cms-api`, `guide/4-media-library.md`.

## Global Constraints

- Żadnej nowej zależności (`standards/dependencies.md`): PNG generowany `zlib`+`struct`, nie Pillow.
- pathlib, `encoding="utf-8"` na każdej operacji na plikach, bez `shell=True`, bez sieci poza istniejącym `docs.py` (git clone tagu).
- Atrapa słucha tylko na `127.0.0.1`. Trasy sterujące `/_tdkit/*` bez tokenu.
- Kolejność sprawdzeń na każdej trasie: zły JSON `422` → `401` → `403` → `422` (schemat tagu, dosłownie, z `additionalProperties`) → `409`.
- Każdy `done_when` scenariusza to dosłowny cytat z `guide/4-media-library.md` tagu (test `test_done_when_quotes_are_literal`).
- Pliki `new_asset` atrapy i plik dla `--media-add-cmd`: PNG 800×600, `image/png`.
- Hosty `file_url` przyjmowane od CMS-a (`POST /media`, `/link`): `127.0.0.1`, `localhost`, dowolny port, `http`/`https`, plus `--media-hosts`. Osobno od `image_hosts`.
- Kursor kanału: `c<run>-<epoch>-<seq>`; `run` = 6 znaków hex na `MockState`; obcy `run` → `422 validation_error` z komunikatem „cursor from an earlier tdkit run: clear the integration's state or pass --reset-cmd”; `epoch` sprzed ponownego włączenia → `410 cursor_expired`.
- Ponowienia dostaw: kody `5xx`, `408`, `425`, `429`, błąd sieci, timeout; harmonogram `(2, 10, 30, 120, 360, 840)` × `retry_scale` sekund.
- Wersje: `tdkit` 1.1.0 (`src/tdkit/__init__.py`), plugin 1.1.0, skill przypina `@v1.1.0`.
- Pełny `pytest` nie biegnie lokalnie (hook): lokalnie tylko `uv run pytest tests/<plik>.py` lub `-k`; całość na CI.

## Review Focus

1. **Ponowne uruchomienie `check` bez `--reset-cmd`** — integracja trzyma kursor z poprzedniego biegu: oczekiwany czytelny błąd 422 i FAIL `l4-first-poll` z podpowiedzią, nie 410 i resync. Test w Task 3.
2. **Więcej niż jedna strona kanału** (`has_more`, >100 zmian): integracja musi czytać do końca w jednym cyklu. Test: scenariusz `l4-new-asset-linked` wrzuca 101 zmian `fields` przed `new_asset` (Task 10), referencja z `--one-page` oblewa.
3. **Wartość pola ze spacjami, cudzysłowem i polskimi znakami w `{value}`** na Windows: jeden argument, bez obcięcia. Test w Task 9 (`render` z wartością `Zażółć "x" y`).
4. **`POST /media/fields` dla pliku jeszcze niesparowanego** odpowiada `unknown`, integracja nie gubi edycji. Test w Task 6 (atrapa) i w `l4-cms-new-file` (Task 10: edycja przed parowaniem dochodzi po parowaniu).
5. **Dwa cykle synchronizacji naraz** (cron + ręczny): referencja trzyma blokadę pliku; atrapa nie musi tego wykrywać — zasada trafia do `generic.md` (Task 12), bez testu w `check` (świadomie: tdkit nie widzi procesów CMS-a).
